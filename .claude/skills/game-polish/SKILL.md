# 게임 폴리싱 스킬

미니게임 1개를 **버그 → 밸런스 → 도파민** 순서로 점검하고 고친다.
전체 전략은 `PHASE7-GAME-POLISH.md` 참조.

## 대원칙

1. **버그가 밸런스보다 먼저, 밸런스가 도파민보다 먼저.** 조작이 안 되는 게임에 이펙트를 넣지 않는다.
2. **게임의 규칙은 바꾸지 않는다.** 스네이크를 테트리스로 만들지 않는다. 조작감·피드백·난이도 곡선만 손본다.
3. **직접 실행해서 확인한다.** 코드만 읽고 "괜찮아 보인다"로 끝내지 않는다.
4. **`shared/juice.js`를 쓴다.** 게임 안에 사운드/파티클을 새로 구현하지 않는다. 없으면 먼저 만든다.

---

## 실행 순서

### 0단계 — 대상 파악

```
1. games.json에서 해당 게임의 title/category/scoreType 확인
   - scoreType: "high"=클수록 좋음, "low"=작을수록 좋음(ms/시간)
2. miniN/index.html 읽기
3. worker/index.js의 GAME_SCORE_LIMITS[miniN] 확인 (점수 상한)
```

### 1단계 — 버그 점검 (필수, 6항목)

| # | 점검 | 확인 방법 | 흔한 증상 |
|---|---|---|---|
| B1 | **터치 조작** | `touchstart\|pointerdown` grep | `mousedown`만 → 모바일 조작 불가 |
| B2 | **재시작 초기화** | 재시작 함수가 모든 상태변수를 리셋하는가 | 점수/레벨/속도가 이월됨 |
| B3 | **타이머 누수** | `setInterval` 개수 vs `clearInterval` 개수 | 재시작마다 루프 중복 → 2배속 |
| B4 | **점수 1회 저장** | `saveScore` 호출 지점 추적 | 게임오버 중복 호출 → 랭킹 도배 |
| B5 | **경계값** | 점수 0 / 즉시종료 / 연타 | 0점 저장 안 됨, 연타 시 중복 시작 |
| B6 | **탭 이탈** | `visibilitychange` 처리 | 백그라운드에서 타이머 폭주 |

**B1은 특히 중요** — 실측상 68/100이 터치 미지원. 발견 즉시 `Juice.bindTap`으로 교체.

```js
// ❌ 모바일 불가
el.addEventListener('mousedown', fn);
el.addEventListener('click', fn);

// ✅ PC + 모바일
Juice.bindTap(el, fn);
```

### 2단계 — 밸런스 점검 (필수, 5항목)

| # | 점검 | 기준 | 조정 방향 |
|---|---|---|---|
| L1 | **첫 10초 생존** | 초보자가 10초는 버티는가 | 초기 속도/스폰율 하향 |
| L2 | **난이도 곡선** | 점진 상승인가 | 계단식 급등 → 선형/로그 곡선으로 |
| L3 | **1판 길이** | 30초~2분 | 너무 길면 재도전 안 함 → 짧게 |
| L4 | **점수 상한 정합** | 실제 도달 최대치 ≈ `GAME_SCORE_LIMITS` | 불일치 시 worker 상수 수정 |
| L5 | **실력 반영** | 잘하면 기록이 오르는가 | 운 100% 게임은 상한만 확인하고 통과 |

**밸런스 수정 시 반드시 근거를 남긴다**: "초기 낙하속도 5→3, 10초 내 사망률 체감 과다" 처럼.

### 3단계 — 도파민 추가 (게임 성격에 맞게 선택)

> 전부 넣지 않는다. 게임에 맞는 2~4개만.

| 요소 | API | 넣을 게임 |
|---|---|---|
| **즉각 피드백** | `Juice.sfx()` + `Juice.buzz()` | **전부** (최소 요건) |
| **개인 최고 갱신** | `Juice.submit(id, score, {isLow})` | **전부** (최소 요건) |
| 콤보 | `Juice.combo.hit()` / `.reset()` | 연속 성공이 있는 게임 (반응/캐치/리듬) |
| 파티클 | `Juice.pop(x, y)` | 대상을 "터뜨리는" 게임 (두더지/블록/캐치) |
| 화면 흔들림 | `Juice.shake(el, power)` | 충돌·피격이 있는 게임 (액션/피하기) |
| 카운트다운 | `Juice.countdown(3, cb)` | 시간제한 게임 |
| 아슬아슬 연출 | 남은 목숨/시간 강조 | 생존형 게임 |

**최소 요건 2개(즉각 피드백 + 최고기록)는 예외 없이 전부 적용한다.**

```js
// 게임오버 표준 패턴 — prompt() 금지
function gameOver() {
  Juice.sfx('gameover');
  Juice.buzz(200);
  Juice.submit(PAGE_ID, score);   // 최고기록 판정 + 연출 + 랭킹 저장 원샷
}
```

### 4단계 — 검증 (필수)

```
① 시스템 — 콘솔 에러 0, 404 없음
② 보안   — 점수 상한 내, 이름 필터 통과, 시크릿 없음
③ 버그   — 1단계 6항목 전부 재확인
④ 실화면 — 로컬 서버에서 실제 플레이 (PC 클릭 + 모바일 에뮬레이션 터치)
```

로컬 실행:
```bash
python -m http.server 8000     # 정적
cd server && npm start          # 랭킹 API (포트 4000)
```
모바일 확인: Chrome DevTools → Toggle device toolbar → 터치로 실제 조작

## 하지 말 것

- ❌ 게임 장르/규칙 변경
- ❌ `prompt()` / `alert()` 사용 (흐름 파괴) → `Juice.toast()` / `Juice.askName()`
- ❌ 게임마다 사운드·파티클 개별 구현 → `juice.js` 사용
- ❌ 코드만 읽고 "정상으로 보임" 결론 → 반드시 실행
- ❌ 도파민 요소 전부 때려넣기 (산만해짐) → 2~4개 선별
- ❌ 밸런스를 "느낌"으로 조정 → 근거(사망률/도달점수) 명시
